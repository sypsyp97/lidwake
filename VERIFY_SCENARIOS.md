# Revision 5 verification through the lidwake executable

Run from the worktree root on macOS as a normal user. Build with `swift build`. Use a fresh fixture for each row. These scenarios describe acceptance on the fixed build.

```sh
fixture=$(mktemp -d)
mkdir "$fixture/home" "$fixture/state"
export CFFIXED_USER_HOME="$fixture/home"
export LIDWAKE_STATE_DIR="$fixture/state"
bin="$(swift build --show-bin-path)/lidwake"
state="$LIDWAKE_STATE_DIR"
dry="$state/dry-run"
mkdir "$dry"
```

Use the built binary at `$bin`. Run the loop only with `--dry-run`. Before either `restore` scenario, decode the journal and confirm `owned=false` and `pending=nil`. Before a read-only check, use `touch -t 200101010000` on the fixture files, then on their parent directory. Record the directory modification time and the files' names, bytes, modes, modification times and inode numbers. Use `stat -f '%N %p %m %i'` for the metadata. Keep reference copies outside the state directory. Compare journal records as JSON and recovery copies byte for byte.

For each failure-log scenario, start `/usr/bin/log stream --style compact --predicate 'subsystem == "dev.lidwake" AND messageType == error'` before launching the command. Capture the CLI process ID (start it in the background and save `$!`) and match that PID in the stream. Check the failing operation in the message. A later tick can also log errors for its own save.
